Vì sao giao diện code ra không giống thiết kế

Root cause của 2 vấn đề sau bước design và hướng xử lý để UI build ra sát thiết kế, giảm thời gian dev phải code lại.

Cập nhật 2026-10-12 · Nguồn: repo fins-treasury, portal-fins, core-ui-catalog

Hai vấn đề đang gặp

2Một số thành phần khác thiết kế vì dev dùng component Core UI, mà prototype-kit và Core UI đang không giống nhau ở phần đó.Designer

Tóm tắt: Hai vấn đề có chung một gốc. Không có kênh nào bắt buộc mang thông tin hình ảnh (khoảng cách, kích thước, component nào) từ prototype sang code. PRISM coi prototype chỉ là tài liệu tham khảo. Giá trị hình ảnh thật nằm trong CSS riêng của prototype, viết bằng class và token của kit, mà các class này ở Core UI lại mang nghĩa khác. Ngoài ra prototype-kit và Core UI là hai design system chạy song song: kit chỉ bắt chước tên thuộc tính của Core UI, còn phần hiển thị vẽ bằng CSS riêng.

Root cause

A

PRISM chỉ bắt buộc hành vi, hình ảnh chỉ là "advisory"

Vấn đề 1
  • .prism/core/conformance-model.md ghi rõ:
    "HTML prototypes… are reference material as a whole and never binding; a difference against a prototype alone routes nowhere."
    Nghĩa là code lệch prototype thì PRISM không coi là lỗi.
  • Trong conformance-defaults.json, field layout bị xếp advisory. phase-implement.md nói: "A visual/layout mismatch is advisory… report it as info".
  • DES-1/DES-2 của bước design chỉ kiểm 4 trạng thái màn hình, câu chữ lỗi, validation và ID phần tử. Không có quy định nào về khoảng cách hay lưới bố cục.
  • Kết quả: trong design-system-v2.md, Layout của SCREEN-036 chỉ là danh sách ID phần tử. Các component chỉ ghi chung chung "spacing scale --space-*", không có con số. AI implement không có số liệu nên phải đoán.
B

Giá trị hình ảnh nằm trong CSS prototype, class của kit mang nghĩa khác ở Core UI

Vấn đề 1
  • treasury-request.css: 3.417 dòng, khoảng 57 khối override, khoảng 377 giá trị px viết cứng.
  • ds-gaps.css: 637 dòng, đang bị copy thành 4 bản (maker, checker, approver, quan-tri).
  • AI implement không đọc hết lượng CSS này, và cũng không port được vì DOM của Angular khác hẳn.

Cùng tên class nhưng khác giá trị là thủ phạm rất có thể của lỗi "fields dính nhau":

Class / cơ chếprototype-kitCore UI (sd-core.scss)
.mb-416px (--space-4)4px
.mb-312pxThang đo px: mb-N = N px
Khoảng cách giữa các field.form-grid-N { gap: 24px }.row gutter 16px, mỗi field tự thêm margin (template dev: col-4 mb-3)

Kit dặn AI "thêm mb-4/mb-6 khi bị dính" (rule 17 trong prototype-kit/CLAUDE.md). Khi copy mb-4 sang portal, khoảng cách còn 4px. Khi bỏ .form-grid-* (portal không có class này), gap 24px mất luôn.

C

Hai design system chạy song song, không ai đồng bộ

Vấn đề 2
  • Các component sd-* trong kit được viết lại theo Figma, không render từ Core UI. Ví dụ: ô nhập size md trong kit cao 36px, Core UI cao 44px (Material density -3).
  • Kit có 18 component sd-*, Core UI có khoảng 60. Khi kit thiếu, prototype tự dựng, còn dev dùng component có sẵn của Core UI nên ra hình khác:
Prototype tự dựngCore UI đã có
Stepper (§1 treasury-request.css)sd-stepper (mat-stepper)
Modal .modal-overlaysd-modal (MatDialog)
Tooltip .tooltip.is-belowmatTooltip
Chip chọn mức độ bảo mật .trf-sec-chipsd-tab-group kiểu segmented, sd-radio
  • AI ở bước design rà sai thư viện: doc ghi "@sd-angular/core 2.1.0 … đã rà package, 0 component", nhưng portal thật dùng ^19.0.8 (catalog dựng từ 19.0.10). Việc phân tích component còn thiếu đã được làm trên kit chứ không phải trên Core UI.
  • Đây là lỗi lặp lại: change pack v1.7.0 và v1.8.0 đều ghi "Design giả định những primitive mà DS đã chọn không có". Mỗi lần đều được sửa sau khi phát hiện, nhưng chưa ai chặn từ gốc.

Cách giải quyết

Quyết định cần chốt trước: khi Figma và Core UI khác nhau thì bên nào thắng? Đề xuất: Core UI thắng mặc định, vì đó là thứ thực sự chạy. Chỗ nào designer muốn giữ theo Figma thì tạo ticket cho FE sửa theme/override, có người chịu trách nhiệm.

Thứ tự đề xuất cho Treasury Request đang build

  1. Ngay: chốt quyết định Core UI thắng mặc định; làm mục 2 (thống nhất class khoảng cách).
  2. Tiếp theo: mục 3 + 4 cho SCREEN-035 → 039. Thu được nhiều nhất, ít tốn công nhất.
  3. Sau đó: mục 5 (sổ khoảng trống DS) và mục 1 (dựng lại kit trên Core UI).
  4. Cuối cùng: mục 6 (so sánh bằng ảnh chụp) và mục 7 (rule chặn từ bước prototype).

Giới hạn của phân tích

  • Số liệu của Core UI lấy từ core-ui-catalog. Đây là bản dựng lại từ bundle, nên cần đối chiếu một lần với app thật (một ảnh chụp là đủ).
  • Chưa xem màn Angular cụ thể mà dev báo lỗi. Việc trùng tên mb-4 là nguyên nhân rất có thể, nhưng nên kiểm chứng trên một ca thật.
